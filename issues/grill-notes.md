# Grill Me — decisions log (CarMart)

| # | Question | Decision |
|---|---|---|
| Q1 | How is a car sold? | (A) Listing marketplace. Buyers browse and contact the shop in-app; payment and handover happen offline. CarMart never handles money for cars in v1. |
| Q2 | Who can open a shop? | (B) Anyone can create a shop and draft listings; the shop goes public only after phone verification + admin approval. Requires an admin role and review queue from day one. One shop per account for now. |
| Q3 | How strict is "no AI images"? | (B) Every image gets two automated checks (is it a car? is it AI-generated?) and lands in pass / clear-fail (rejected, reason shown) / uncertain (admin review queue). A listing goes public only when all its photos pass. 4–20 photos per listing; re-check on every edit; shops with repeated AI/non-car rejections get flagged. PRD wording: "every image is checked; suspicious images are blocked or reviewed" — no 100% guarantee is promised. |
| Q4 | Which services run the image checks? | (B) on a swappable foundation: all checks go through one ImageVerificationService with pluggable providers (fake provider in dev/tests, no paid calls in tests). Defaults: Claude vision for the car check (structured output: is_car, view type exterior/interior/engine/dashboard, screen/printout, plate/face visible); Sightengine for AI detection, Hive as backup. Vendor pricing/accuracy to be confirmed at sign-up. |
| Q5 | Monetisation / who pays checks? | (A) Free in v1; CarMart carries image-check costs. Guardrails: max 10 active listings per shop (admin can raise per shop), max 60 photo uploads per shop per day. shops.plan column defaults to "free" so paid plans can be added later without rework. No payments/Stripe in v1. |
| Q6 | Launch market? | (A) One country: Australia. AUD, kilometres, AU phone numbers (+61) for SMS verification, Australian Privacy Act / Australian Consumer Law for legal pages, state + suburb/postcode location. Currency, units and country stored on shops/listings (not hard-coded) so other countries can be added later. |
| Q7 | Listing contents / "cars only" on the data side | (B) Structured listing: make + model from a car-only reference list ("Other" → admin review), year, odometer (km), price (AUD), body type (sedan, hatchback, SUV, wagon, coupe, convertible, ute, people mover), transmission, fuel, colour, state + suburb/postcode, VIN (required, 17 chars, format-validated, shown publicly for PPSR checks), rego + expiry (optional), description. Excluded: trucks, buses, motorbikes, caravans, boats, parts. |
| Q8 | Listing lifecycle | draft → checking → live / in_review / rejected; live → sold / expired (60 days, renewable → checking); admin → removed (terminal, reason recorded). One active listing per VIN platform-wide (duplicate → in_review with side-by-side admin view). Live edits: text/price instant; new photos checked before shown (old stay up); VIN/make/model/year change → back to checking. Sold shows SOLD banner 7 days then leaves search. Sold/expired don't count toward the 10-listing cap. |

> From Q9 onward the user delegated: "From now on use your recommendations." Q9–Q20 are Claude's recommendations, accepted by delegation.

| # | Topic | Decision |
|---|---|---|
| Q9 | Accounts & roles | Browsing is public, no account needed. Signing in required to contact a shop, save cars or report. One account type (`user`); a user becomes a seller by creating their shop. Separate `admin` role, granted only via database (never self-service). |
| Q10 | Buyer ↔ seller contact | In-app message threads, one per (buyer, listing). Text only — no attachments (keeps "car images only" absolute). Email notification on new message. Seller phone hidden by default; shop can enable "show phone to signed-in buyers". Buyer limit: 20 new conversations per day. Users can block a conversation and report it. |
| Q11 | Authentication | Supabase Auth: email + password with email verification, plus Google sign-in. Shop owners additionally verify an Australian mobile (+61) via SMS OTP (Supabase phone auth / Twilio) before submitting a shop for approval. |
| Q12 | Search & browse | Filters: make, model, price range, year range, max km, body type, transmission, fuel, state, suburb/postcode. Sort: newest, price ↑/↓, km ↑, year ↓. 24 results per page. Postgres full-text search on make/model/description. Signed-in users can save cars (watchlist). Radius search and saved-search alerts are out of scope for v1. |
| Q13 | Shop page & non-car uploads | Public shop page `/shops/[slug]`: name, description, suburb/state, "Verified shop" badge (approved + phone verified), member since, active listings. NO logo/avatar/cover uploads in v1 — initials avatar only — so the only images anyone can upload anywhere are car photos. |
| Q14 | Admin tools | Admin area `/admin`: shop approval queue, image review queue (shows scores, reasons, and the photo), duplicate-VIN review, reports queue, remove listing (with reason), suspend/unsuspend shop or user, raise a shop's listing cap, "Other" make/model review. Every admin action written to an append-only audit log. |
| Q15 | Reporting | Any signed-in user can report a listing, shop or conversation with a reason (scam, not a car, AI/fake photos, wrong details, offensive, other) + optional note. Reports go to the admin reports queue. A listing with 3+ open reports from different users is auto-hidden to in_review. |
| Q16 | Image pipeline | Browser uploads straight to a PRIVATE quarantine bucket via signed upload URL. Accept JPEG/PNG/WebP/HEIC, ≤ 10 MB, ≥ 800×600. Worker runs: format/size validation → perceptual hash (same image already used by a different shop → in_review) → metadata signals recorded → car check (Claude vision) → AI check (Sightengine). Then: strip ALL metadata (removes GPS), convert to WebP in 3 sizes, copy to PUBLIC bucket. Starting thresholds (admin-configurable in app_settings): AI score ≥ 0.90 reject, 0.50–0.89 review, < 0.50 pass; car check "not a car" at high confidence → reject, low confidence → review; screen/printout photo → review. Worker = Supabase Edge Function fed by an image_checks job table; idempotent; up to 3 retries, then in_review. Plate/face flags stored; automatic blurring out of scope for v1. |
| Q17 | Notifications | Transactional email via Resend: email verification, shop approved/rejected, listing live / rejected (with reasons) / in review, new message, listing expiring in 7 days. No SMS except the verification OTP. |
| Q18 | Legal & trust pages | Terms of Use, Privacy Policy (Australian Privacy Act), Prohibited Listings policy (cars only), Buyer Safety tips (PPSR check link, inspect before paying, never pay deposits off-platform to strangers), Contact page. Static pages; lawyer review before launch flagged as a human task. |
| Q19 | Quality bar | Mobile-first responsive; WCAG 2.1 AA; listing and shop pages server-rendered with SEO metadata, Open Graph images, sitemap.xml; rate limits on auth, uploads, messaging, reports; RLS on every table; hosting on Vercel + hosted Supabase in the Sydney region (ap-southeast-2) so data stays in Australia. |
| Q20 | Testing | Vitest unit tests for services; integration tests against local Supabase including RLS policy tests (every table: owner vs other user vs anonymous vs admin); image providers replaced by a fake provider with fixture images in all automated tests; Playwright end-to-end for the core journeys (seller onboarding → approval → listing goes live; buyer search → enquiry; admin review). |

# API Contracts

> The source of truth for every CarMart API route. Generated by /write-specs from `issues/prd-carmart.md`.
> Route handlers are thin: **Zod parse → session → auth/role check → service → structured response** (CLAUDE.md).

---

## Conventions

- Base path: `/api`. JSON in and out. Every request body is validated with Zod at the route handler. Unknown keys are **rejected** (`.strict()`).
- Success: `{ "data": T }`. Paginated: `{ "data": T[], "page": { "number": 1, "size": 24, "total": 137 } }`.
- Error: `{ "error": { "code": "SNAKE_CASE_CODE", "message": "Human-readable, safe to show" } }`. Internal error details are never returned.
- Status codes: 200 OK, 201 Created, 204 No Content, 400 malformed JSON, 401 not signed in, 403 forbidden / suspended / blocked, 404 not found or not visible to the caller, 409 conflict, 422 validation or business rule, 429 rate limit, 500 unexpected.
- **Auth levels:**
  - `public`: no session needed
  - `user`: signed in with a verified email and `status = 'active'`
  - `owner`: `user` who owns the shop or listing
  - `admin`: `user` with `role = 'admin'`
- Ids are UUIDs (`z.string().uuid()`). Money is in **cents** (integer). Timestamps are ISO-8601 UTC.
- Pages (RSC) read data by calling services directly on the server. These routes serve client-side mutations and client fetches.

### Shared Zod building blocks (`src/types/domain.ts`)

```typescript
export const AuStateSchema = z.enum(['NSW','VIC','QLD','WA','SA','TAS','ACT','NT'])
export const BodyTypeSchema = z.enum(['sedan','hatchback','suv','wagon','coupe','convertible','ute','people_mover'])
export const TransmissionSchema = z.enum(['automatic','manual'])
export const FuelSchema = z.enum(['petrol','diesel','hybrid','plug_in_hybrid','electric','lpg'])
export const VinSchema = z.string().trim().toUpperCase().regex(/^[A-HJ-NPR-Z0-9]{17}$/, 'INVALID_VIN')
export const PostcodeSchema = z.string().regex(/^\d{4}$/)
export const SlugSchema = z.string().min(3).max(50).regex(/^[a-z0-9]+(-[a-z0-9]+)*$/)
export const AuMobileSchema = z.string().regex(/^\+614\d{8}$/, 'INVALID_AU_MOBILE') // E.164 AU mobile
```

### Global error codes

| Code | Status | When |
|---|---|---|
| `VALIDATION_ERROR` | 422 | Zod failure (the message names the first failing field) |
| `UNAUTHENTICATED` | 401 | No session |
| `EMAIL_NOT_VERIFIED` | 403 | Session exists but the email is unverified |
| `ACCOUNT_SUSPENDED` | 403 | Profile `status = 'suspended'` |
| `FORBIDDEN` | 403 | Wrong role, or not the owner |
| `NOT_FOUND` | 404 | Missing, or not visible to the caller |
| `INVALID_STATE` | 409 | The action isn't allowed from the current status |
| `VERSION_CONFLICT` | 409 | Optimistic lock failure (`version` mismatch) |
| `RATE_LIMITED` | 429 | Generic limit (auth endpoints) |
| `INTERNAL_ERROR` | 500 | Unexpected; logged with a request id |

## Auth and profile

Sign-up, sign-in, sign-out, Google OAuth and email verification use the **Supabase Auth client SDK** directly (see `docs/auth.md`). The app provides:

### GET /auth/callback
**Auth:** public. Exchanges the OAuth or email-confirmation `code` for a session cookie, then redirects to `next` (validated to be a relative path) or `/`.

### GET /api/profile/me
**Auth:** user
**Success, 200:** `{ "data": { "id", "display_name", "role", "phone": "+614…" | null, "phone_verified": true, "has_shop": true } }`

### PATCH /api/profile/me
**Auth:** user
**Request:** `z.object({ display_name: z.string().trim().min(1).max(60) }).strict()`
**Success, 200:** the updated profile. **Errors:** 401, 403, 422.

### POST /api/profile/phone/send-code
**Auth:** user
**Request:** `z.object({ phone: AuMobileSchema }).strict()`
**Behaviour:** calls `supabase.auth.updateUser({ phone })`, which sends an SMS OTP. Limited to 5 per hour per user.
**Success, 200:** `{ "data": { "sent": true } }`
**Errors:** 422 `INVALID_AU_MOBILE`, 429 `RATE_LIMITED`, 409 `PHONE_IN_USE` (the number is already verified on another account).

### POST /api/profile/phone/verify
**Auth:** user
**Request:** `z.object({ phone: AuMobileSchema, code: z.string().regex(/^\d{6}$/) }).strict()`
**Behaviour:** `supabase.auth.verifyOtp({ phone, token, type: 'phone_change' })`. A trigger copies `phone_confirmed_at` into `profiles.phone_verified_at`.
**Success, 200:** `{ "data": { "phone_verified": true } }`
**Errors:** 422 `INVALID_CODE`, 429 `RATE_LIMITED`.

## Shops

### POST /api/shops
**Auth:** user
**Request:**
```typescript
z.object({
  name: z.string().trim().min(2).max(60),
  slug: SlugSchema,
  description: z.string().trim().max(1000).optional(),
  suburb: z.string().trim().min(2).max(60),
  state: AuStateSchema,
  postcode: PostcodeSchema,
}).strict()
```
**Success, 201:** `{ "data": Shop }` with `status: "draft"`.
**Errors:** 401, 403, 409 `SHOP_ALREADY_EXISTS`, 409 `SLUG_TAKEN`, 422 `POSTCODE_STATE_MISMATCH`, 422 `VALIDATION_ERROR`.

### GET /api/shops/me
**Auth:** user. **Success, 200:** `{ "data": Shop }`. **Errors:** 404 when the user has no shop.

### PATCH /api/shops/me
**Auth:** owner
**Request:** partial of the POST body plus `show_phone: z.boolean()`. `slug` is accepted only while `status ∈ {draft, rejected}`, otherwise 409 `SLUG_LOCKED`.
**Success, 200:** `{ "data": Shop }`. **Errors:** 403 (suspended shop), 409, 422.

### POST /api/shops/me/submit
**Auth:** owner
**Behaviour:** `draft | rejected → pending_approval` (`docs/systems/shop-onboarding.md`).
**Success, 200:** `{ "data": Shop }`
**Errors:** 409 `INVALID_STATE`, 422 `PHONE_NOT_VERIFIED`.

### Shop (response shape)
```json
{ "id": "uuid", "name": "Coastal Cars", "slug": "coastal-cars", "description": "…",
  "suburb": "Parramatta", "state": "NSW", "postcode": "2150", "status": "approved",
  "status_reason": null, "verified": true, "show_phone": false, "listing_cap": 10,
  "active_listing_count": 3, "created_at": "2026-09-28T10:00:00Z" }
```
`status_reason`, `listing_cap` and `active_listing_count` are returned to the owner and admins only.

## Listings

### ListingInput (Zod)
```typescript
export const ListingInputSchema = z.object({
  make_id: z.string().uuid().nullable(),
  make_other: z.string().trim().min(2).max(40).nullable(),
  model_id: z.string().uuid().nullable(),
  model_other: z.string().trim().min(1).max(40).nullable(),
  year: z.number().int().min(1900).max(new Date().getFullYear() + 1),
  odometer_km: z.number().int().min(0).max(2_000_000),
  price_cents: z.number().int().min(100).max(1_000_000_000),
  body_type: BodyTypeSchema,
  transmission: TransmissionSchema,
  fuel: FuelSchema,
  colour: z.string().trim().min(2).max(30),
  vin: VinSchema,
  rego: z.string().trim().toUpperCase().regex(/^[A-Z0-9]{1,9}$/).nullable(),
  rego_expiry: z.string().date().nullable(),
  description: z.string().trim().max(5000),
  state: AuStateSchema,
  suburb: z.string().trim().min(2).max(60),
  postcode: PostcodeSchema,
}).strict()
  .refine(v => (v.make_id === null) !== (v.make_other === null), 'MAKE_REQUIRED')
  .refine(v => (v.model_id === null) !== (v.model_other === null), 'MODEL_REQUIRED')
```

### POST /api/listings
**Auth:** owner (must own a shop that isn't `suspended`)
**Request:** `ListingInputSchema.partial()`, so drafts may be incomplete. Every field present is validated.
**Success, 201:** `{ "data": Listing }` with `status: "draft"`.
**Errors:** 403, 404 `SHOP_NOT_FOUND`, 422.

### PATCH /api/listings/:id
**Auth:** owner
**Request:** `ListingInputSchema.partial()` plus `version: z.number().int()`
**Behaviour** (edit rules, `docs/systems/listing-lifecycle.md`):
- `draft`, `rejected`, `expired`: any field.
- `live`: `colour`, `rego`, `rego_expiry`, `description`, `price_cents`, `odometer_km`, `suburb`, `postcode` and `state` apply immediately. Changing `vin`, `make_*`, `model_*` or `year` moves the listing to `checking`.
- `checking`, `in_review`: 409 `INVALID_STATE` (wait for the result).
- `sold`, `removed`: 409 `INVALID_STATE`.

**Success, 200:** `{ "data": Listing }`
**Errors:** 404, 409 `INVALID_STATE`, 409 `VERSION_CONFLICT`, 422.

### DELETE /api/listings/:id
**Auth:** owner. Allowed only for `draft` listings. **Success:** 204. **Errors:** 404, 409 `INVALID_STATE`.

### POST /api/listings/:id/submit
**Auth:** owner. **Request:** `z.object({ version: z.number().int() }).strict()`
**Behaviour:** validates completeness against the full `ListingInputSchema`, 4–20 non-deleted photos, the shop cap, the active-VIN duplicate check and the make/model "Other" check. Then `draft | rejected | expired → checking`.
**Success, 200:** `{ "data": Listing }`
**Errors:** 409 `INVALID_STATE`, 409 `VERSION_CONFLICT`, 422 `LISTING_INCOMPLETE` (message lists the missing fields), 422 `PHOTO_COUNT`, 422 `LISTING_LIMIT_REACHED`, 422 `SHOP_NOT_APPROVED` (only approved shops can submit; drafting is allowed before approval).

### POST /api/listings/:id/mark-sold
**Auth:** owner. `live → sold`. **Success, 200:** `{ "data": Listing }`. **Errors:** 409 `INVALID_STATE`.

### POST /api/listings/:id/renew
**Auth:** owner. `expired → checking` (re-runs photo checks and the VIN uniqueness check). **Success, 200.** **Errors:** 409 `INVALID_STATE`, 422 `LISTING_LIMIT_REACHED`.

### GET /api/listings (search)
**Auth:** public
**Query** (`z.object({...}).strict()`, all optional):
`q` (string ≤ 100), `make_id`, `model_id`, `price_min`, `price_max` (cents), `year_min`, `year_max`, `km_max`, `body_type`, `transmission`, `fuel`, `state`, `suburb`, `postcode`, `sort` ∈ `newest | price_asc | price_desc | km_asc | year_desc` (default `newest`), `page` ≥ 1 (default 1).
**Behaviour:** only `live` listings of `approved` shops; filters combine with AND; 24 per page.
**Success, 200:**
```json
{ "data": [ { "id": "uuid", "title": "2019 Toyota HiLux SR5", "price_cents": 4599000, "currency": "AUD",
  "year": 2019, "odometer_km": 84000, "body_type": "ute", "transmission": "automatic", "fuel": "diesel",
  "suburb": "Toowoomba", "state": "QLD", "thumbnail_url": "https://…/sm.webp",
  "shop": { "name": "Darling Downs Autos", "slug": "darling-downs-autos", "verified": true },
  "live_at": "2026-09-20T02:00:00Z" } ],
  "page": { "number": 1, "size": 24, "total": 137 } }
```
**Errors:** 422 `VALIDATION_ERROR`.

### GET /api/listings/:id
**Auth:** public for `live`, and for `sold` within 7 days; the owner and admins see any status.
**Success, 200:** `{ "data": ListingDetail }`, with all fields, ordered photo URLs (`sm`/`md`/`lg`), `ppsr_url: "https://www.ppsr.gov.au/"`, shop summary and `is_saved` (for signed-in users). The owner also gets per-photo `status` and `status_reason`, and the listing's `status_reason` and `review_flags` (as seller-facing text).
**Errors:** 404.

### GET /api/listings/:id/phone
**Auth:** user
**Success, 200:** `{ "data": { "phone": "+61412345678" } }` only when the listing is publicly visible and the shop has `show_phone = true`.
**Errors:** 401, 404 `PHONE_NOT_AVAILABLE`.

### GET /api/shops/me/listings
**Auth:** owner. **Query:** `status` (optional), `page`. **Success, 200:** paginated `Listing[]` including photo status counts.

## Listing photos

### POST /api/listings/:id/images
**Auth:** owner. Listing status ∈ {`draft`, `rejected`, `expired`, `live`}.
**Request:**
```typescript
z.object({
  mime_type: z.enum(['image/jpeg','image/png','image/webp']), // HEIC converted client-side (ADR-007)
  bytes: z.number().int().min(1).max(10_485_760),
}).strict()
```
**Behaviour:** checks the photo cap (20 non-deleted) and the shop's 60-per-24h upload limit, creates a `listing_images` row (`uploaded`), records an `upload_events` row, and returns a **signed upload URL** for the quarantine path (single object, no overwrite). Supabase fixes signed upload URLs at 2 hours, so `expires_in` is 7200; an `uploaded` photo that never completes is soft-deleted after 2 hours so it stops counting toward the 20-photo cap.
**Success, 201:** `{ "data": { "image_id": "uuid", "upload_url": "https://…", "expires_in": 7200 } }`
**Errors:** 409 `INVALID_STATE`, 422 `PHOTO_COUNT`, 422 `VALIDATION_ERROR` (type/size), 429 `UPLOAD_LIMIT`.

### POST /api/listings/:id/images/:imageId/complete
**Auth:** owner
**Behaviour:** confirms the object exists in quarantine and its size matches, then calls `enqueue_image_check(image_id)` → `listing_images.status = checking`, `image_checks` row `queued`. Idempotent: calling twice returns the same job.
**Success, 202:** `{ "data": { "image_id": "uuid", "status": "checking" } }`
**Errors:** 404, 409 `UPLOAD_MISSING`.

### DELETE /api/listings/:id/images/:imageId
**Auth:** owner. Soft-deletes the photo. On a `live` listing this is refused if it would leave fewer than 4 **passed** photos (422 `PHOTO_COUNT`). **Success:** 204.

### PUT /api/listings/:id/images/order
**Auth:** owner. **Request:** `z.object({ image_ids: z.array(z.string().uuid()).min(1).max(20) }).strict()`. It must contain exactly the listing's non-deleted image ids. **Success, 200.** **Errors:** 422 `VALIDATION_ERROR`.

### GET /api/listings/:id/images/status
**Auth:** owner. Polled by the seller UI every 3 s while any photo is `checking`.
**Success, 200:** `{ "data": [{ "image_id", "position", "status", "status_reason", "thumbnail_url" | null }] }`. Thumbnails of photos that haven't passed are short-lived signed quarantine URLs for the owner only.

## Conversations and messages

### POST /api/conversations
**Auth:** user
**Request:** `z.object({ listing_id: z.string().uuid(), body: z.string().trim().min(1).max(2000) }).strict()`
**Behaviour:** the listing must be `live`, and the caller must not be the shop owner. Returns the existing thread (and appends the message) if one exists. Only a *new* thread counts toward the 20-per-24h limit.
**Success, 201 (new) / 200 (existing):** `{ "data": { "conversation_id": "uuid" } }`
**Errors:** 404, 403 `OWN_LISTING`, 403 `CONVERSATION_BLOCKED`, 429 `CONVERSATION_LIMIT`.

### GET /api/conversations
**Auth:** user. Threads where the caller is the buyer or the shop owner, newest activity first, with `unread_count` and the listing summary. Paginated (24).

### GET /api/conversations/:id/messages
**Auth:** participant (admins: only if the conversation has a report). **Query:** `before` (ISO timestamp, optional), 50 per page. Marks incoming messages read.

### POST /api/conversations/:id/messages
**Auth:** participant
**Request:** `z.object({ body: z.string().trim().min(1).max(2000) }).strict()`. No attachments exist in the contract; any extra key → 422.
**Success, 201:** `{ "data": Message }`
**Errors:** 403 `CONVERSATION_BLOCKED`, 404, 422.

### POST /api/conversations/:id/block
**Auth:** participant. Sets `blocked_by = caller`. **Success:** 204. After this, the *other* participant gets 403 `CONVERSATION_BLOCKED` on send.

## Reports

### POST /api/reports
**Auth:** user
**Request:**
```typescript
z.object({
  target_type: z.enum(['listing','shop','conversation']),
  target_id: z.string().uuid(),
  reason: z.enum(['scam','not_a_car','ai_or_fake_photos','wrong_details','offensive','other']),
  note: z.string().trim().max(1000).optional(),
}).strict()
```
**Behaviour:** the target must be visible to the reporter (a conversation: must be a participant). One open report per user per target. 10 per 24h per user. If a listing reaches 3 open reports from distinct users, it moves to `in_review` with the flag `reports_threshold`.
**Success, 201:** `{ "data": { "id": "uuid" } }`
**Errors:** 404, 409 `ALREADY_REPORTED`, 429 `REPORT_LIMIT`.

## Admin (all routes: Auth `admin`, otherwise 403 `FORBIDDEN`)

Every mutating admin route requires `reason` where noted, writes one `admin_actions` row in the same transaction, and returns `{ "data": <updated entity> }`.

| Method & path | Body (Zod, `.strict()`) | Effect |
|---|---|---|
| GET `/api/admin/queues/:queue` | query `page` | `queue` ∈ `shops`, `images`, `duplicate-vins`, `other-make-model`, `reports`. Oldest first. The images queue items include a signed quarantine URL, `car_check`, `ai_check`, `metadata_signals`, `phash_match` and the listing context. Duplicate VIN items include both listings. |
| POST `/api/admin/shops/:id/approve` | `{}` | `pending_approval → approved`; email owner |
| POST `/api/admin/shops/:id/reject` | `{ reason: string 5–500 }` | `pending_approval → rejected`; email owner |
| POST `/api/admin/shops/:id/suspend` | `{ reason }` | → `suspended`; listings leave search immediately |
| POST `/api/admin/shops/:id/unsuspend` | `{ reason }` | `suspended → approved` |
| PATCH `/api/admin/shops/:id/listing-cap` | `{ listing_cap: int 1–1000, reason }` | Sets the cap |
| POST `/api/admin/images/:id/approve` | `{}` | Image `in_review → passed`; publishes variants; re-evaluates the listing |
| POST `/api/admin/images/:id/reject` | `{ reason }` | Image → `rejected`; re-evaluates the listing |
| POST `/api/admin/listings/:id/clear-flag` | `{ flag: review_flag, reason? }` | Removes one review flag (`duplicate_vin`, `other_make_model`, `reports_threshold`); re-evaluates the listing |
| POST `/api/admin/listings/:id/reject` | `{ reason }` | `in_review → rejected` (the seller can fix and resubmit) |
| POST `/api/admin/listings/:id/remove` | `{ reason }` | Any → `removed` (terminal); unpublishes photos; email owner |
| POST `/api/admin/reports/:id/dismiss` | `{ reason }` | `open → dismissed` |
| POST `/api/admin/reports/:id/action` | `{ reason }` | `open → actioned` (used alongside remove/suspend) |
| POST `/api/admin/users/:id/suspend` | `{ reason }` | Profile → `suspended`; their shop → `suspended` |
| POST `/api/admin/users/:id/unsuspend` | `{ reason }` | Profile → `active` (the shop stays suspended until unsuspended separately) |
| GET `/api/admin/settings` | — | All `app_settings` |
| PATCH `/api/admin/settings` | `{ key: enum of seeded keys, value: number }` | Validated per key (see `docs/schema.md`); writes `admin_actions` |
| GET `/api/admin/audit-log` | query `page`, `target_type?`, `target_id?` | Newest first, 50 per page |

**Common admin errors:** 404, 409 `INVALID_STATE`, 422 `REASON_REQUIRED`, 422 `VALIDATION_ERROR`.

## Internal (not called by browsers)

All internal routes live under `src/app/api/internal/*`, run in the **Node.js runtime** (`export const runtime = 'nodejs'`, `maxDuration = 60`), and require `Authorization: Bearer ${INTERNAL_JOB_SECRET}` (constant-time compare). Anything else → 401 with no details. They're called only by Postgres (`pg_net` from triggers and pg_cron). They delegate to `src/server/jobs/**`, the **only** code allowed to create a service-role Supabase client (ADR-006).

### POST /api/internal/process-image-checks
**Request:** `z.object({ job_id: z.string().uuid().optional() }).strict()`. Without `job_id`, it claims up to 5 queued jobs (`FOR UPDATE SKIP LOCKED`).
**Behaviour:** `docs/systems/image-verification.md`. **Response, 200:** `{ "data": { "processed": 3 } }`

### POST /api/internal/dispatch-notifications
**Request:** `{}`. Claims up to 50 `pending` notifications, renders the templates, sends through Resend, and marks each `sent`. On failure it retries (up to 5 attempts), then marks it `failed`. **Response, 200:** `{ "data": { "sent": 12 } }`

### POST /api/internal/purge-quarantine
**Request:** `{}`. Deletes quarantine objects older than 30 days. **Response, 200:** `{ "data": { "deleted": 40 } }`

### POST /api/internal/unpublish-listing
**Request:** `z.object({ listing_id: z.string().uuid() }).strict()`. Deletes every public WebP variant for the listing and nulls `public_paths`. Idempotent. Called by the trigger when a listing becomes `removed`, and by `unpublish_old_sold()`. **Response, 200:** `{ "data": { "deleted": 18 } }`

### POST /api/internal/unpublish-image
**Request:** `z.object({ image_id: z.string().uuid() }).strict()`. Deletes one image's public variants (an admin rejecting a previously passed photo, or a seller deleting a passed photo). Idempotent.

There are no browser-facing cron routes.

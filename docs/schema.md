# Database Schema

> The source of truth for every CarMart Supabase table. Generated by /write-specs from `issues/prd-carmart.md`.
> Postgres 15 (Supabase). Every table has RLS enabled.

---

## Conventions

- Primary keys: `id uuid primary key default gen_random_uuid()`, except `profiles.id` (= `auth.users.id`) and `app_settings.key`.
- Every mutable table has `created_at timestamptz not null default now()` and `updated_at timestamptz not null default now()`, with `updated_at` kept current by the trigger `set_updated_at()`.
- Money is stored in **integer cents** (`price_cents bigint`), with a `currency char(3)`.
- Helper SQL functions (all `security definer`, `stable`, with an explicit `search_path = public`):
  - `is_admin()`: true when `profiles.role = 'admin'` and `status = 'active'` for `auth.uid()`
  - `owns_shop(shop_id uuid)`: true when `shops.owner_id = auth.uid()`
  - `is_active_user()`: true when the caller's profile `status = 'active'`
- **Service role**: used only by the background job runner in `src/server/jobs/**` (image checks and email dispatch), reached through `/api/internal/*` routes authenticated with `INTERNAL_JOB_SECRET` (ADR-006). User-facing route handlers never use the service role. Admin actions run as the admin user and are allowed by `is_admin()` policies.

## Tables

### profiles

**Purpose:** Application data for each auth user. A row is created by the trigger `handle_new_user()` on `auth.users` insert.

| Column | Type | Nullable | Default | Description |
|---|---|---|---|---|
| `id` | `uuid` | NO | — | PK, FK → `auth.users.id` on delete cascade |
| `display_name` | `text` | NO | — | 1–60 chars; defaults to the email local part on creation |
| `role` | `user_role` | NO | `'user'` | Only changeable by migration or seed (see RLS) |
| `status` | `account_status` | NO | `'active'` | `suspended` blocks all protected routes |
| `phone` | `text` | YES | null | E.164 `+61…`; mirrors `auth.users.phone` after verification |
| `phone_verified_at` | `timestamptz` | YES | null | Copied from `auth.users.phone_confirmed_at` by trigger |
| `created_at` / `updated_at` | `timestamptz` | NO | `now()` | |

**Indexes:** PK only.

**RLS Policies:**
| Policy | Operation | Condition |
|---|---|---|
| Read own profile | SELECT | `id = auth.uid()` |
| Admins read all | SELECT | `is_admin()` |
| Update own display name | UPDATE | `id = auth.uid()`. A column-level grant allows only `display_name`; `role`, `status`, `phone*` are not updatable by `authenticated` |
| Admins change status | UPDATE | `is_admin()`. Column grant covers `status` only |
| No client insert/delete | INSERT/DELETE | none (trigger and cascade only) |

| Policy | Operation | Condition |

| Admins read all | SELECT | `is_admin()` |
| Owner creates draft | INSERT | `owns_shop(shop_id) AND status = 'draft' AND is_active_user()` |
| Owner updates own editable fields | UPDATE | `owns_shop(shop_id) AND status NOT IN ('removed')`. Status transitions only through `security definer` RPCs (`submit_listing`, `mark_listing_sold`, `renew_listing`) that enforce `docs/systems/listing-lifecycle.md` |
| Owner deletes draft | DELETE | `owns_shop(shop_id) AND status = 'draft'` |
| Admins update | UPDATE | `is_admin()` |

|---|---|---|---|---|
| `id` | `uuid` | NO | `gen_random_uuid()` | PK |
| `user_id` | `uuid` | NO | — | Recipient (email is looked up from `auth.users` at send time) |
| `kind` | `text` | NO | — | `shop_approved`, `shop_rejected`, `listing_live`, `listing_rejected`, `listing_in_review`, `listing_removed`, `listing_expiring`, `new_message` |
| `ref_id` | `uuid` | YES | null | Related entity (shop, listing or conversation) |
| `payload` | `jsonb` | NO | `'{}'` | Template variables (reasons, titles, links) |
| `status` | `text` | NO | `'pending'` | `pending`, `sent`, `failed`, `skipped` |
| `attempts` | `smallint` | NO | `0` | Max 5, then `failed` |
| `sent_at` | `timestamptz` | YES | null | |
| `created_at` | `timestamptz` | NO | `now()` | |

**Rules (enforced by the enqueue function `enqueue_notification`):**
- `new_message`: skipped if a `new_message` for the same `ref_id` (conversation) and `user_id` was queued in the last 15 minutes (AC-46).
- `listing_expiring`: at most one per listing per live period.

**Indexes:** `(status, created_at) WHERE status = 'pending'`; `(user_id, kind, ref_id, created_at desc)`.
**RLS:** no client access (service role and security definer functions only).

## Storage buckets

| Bucket | Public | Write | Read |
|---|---|---|---|
| `listing-quarantine` | NO | Owner, via a signed upload URL for `{shop_id}/{listing_id}/{image_id}` only (insert, no overwrite) | Service role (worker) and admins (signed URLs for the review queue) |
| `listing-public` | YES | Service role (worker) only | Public (only passed, metadata-stripped WebP variants ever land here) |

Removing a listing or rejecting an image deletes its public variants (worker/RPC). Quarantine originals are kept for 30 days for review and audit, then purged.

## Scheduled jobs (pg_cron)

| Job | Schedule | Action |
|---|---|---|
| `expire_listings()` | every 15 min | `live` listings with `expires_at < now()` → `expired` |
| `queue_expiry_reminders()` | hourly | live listings expiring within `expiry_reminder_days` without a reminder → enqueue `listing_expiring` + set `expiry_reminder_sent_at` |
| `requeue_stale_checks()` | every 5 min | `running` image jobs locked > 5 min → `queued` (attempts already counted) |
| `pg_net` POST `/api/internal/process-image-checks` | every minute | safety net; the main trigger is an `AFTER INSERT` trigger on `image_checks` calling `pg_net` |
| `pg_net` POST `/api/internal/dispatch-notifications` | every minute | safety net; also triggered after insert on `notifications` |
| `unpublish_old_sold()` | daily 02:30 Australia/Sydney | `pg_net` POST `/api/internal/unpublish-listing` for sold listings past `sold_visible_days` |
| `purge_old_rows()` | daily 03:00 Australia/Sydney | `upload_events` > 7 days; `pg_net` POST `/api/internal/purge-quarantine` for quarantine objects > 30 days |

All `pg_net` calls send `Authorization: Bearer <INTERNAL_JOB_SECRET>`. The secret and the app URL are stored in Supabase Vault (`internal_job_secret`, `app_base_url`).
